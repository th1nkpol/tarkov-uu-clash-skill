# 脱敏案例：俄区塔科夫登录与更新

参考环境为 Windows、Clash Verge Rev 2.5.7、Mihomo 1.19.32。账号为俄区，UU 使用“俄服登录解锁”。本文件只保留公开域名、技术现象和用户结果，未包含节点、订阅、私人路径或认证信息。

## 登录

Clash 与 UU 同开时，启动器登录返回 Forbidden。核心里的相关连接虽命中 DIRECT，仍不代表 UU 已按启动器进程接管。

关闭 TUN、保持规则模式和系统代理、加入登录域名绕过之后，仅重开启动器仍发生约 21 秒超时。清理系统 DNS 缓存后虚拟映射仍存在。停止并重新开启同一 UU 俄服登录解锁，再重开启动器，用户确认登录恢复。

具体底层冲突未完全隔离，因此不能将所有 403 或虚拟 DNS 地址归因于 Clash，也不能承诺相同操作解决所有环境。

## 更新

更新涉及 `node06-101` 至 `node06-110.eft-store.com` 与 `cdn-11.eft-store.com`。初始更新路径为启动器进入 Clash，再由 Clash DIRECT，短时流量增量约 0.19 MB/s。

临时把更新 CDN 送入代理节点，用户观察约 3 MB/s，低于此前 UU 接近 20 MB/s 的表现。最终撤销该代理试验，把 `eft-store.com;*.eft-store.com` 加入系统代理绕过名单，并重开启动器。用户确认更新速度接近 20 MB/s。

最终核心中没有这些更新 CDN 连接；启动器有 15 个到 UU 本机端口的连接，另有两个非更新后台连接到 Clash。.NET Framework 代理检查显示登录与更新域名被绕过。

## 结论边界

已确认的是登录恢复、更新提速以及所观察的连接变化。对局、俄区出口和切换订阅后的实际游戏行为未单独验证，20 MB/s 是案例观察值。

可复用的方法是分清系统代理入口与核心 DIRECT，并分别验证登录和更新。全局规则与绕过项可独立于节点订阅保留；切换后仍需核对有效配置。此方法不需要改变云服务器、账户或设备密钥。
